# Continuous Monitoring Overview - FedRAMP Documentation ## Key Content Summary **Foundation:** FedRAMP's continuous monitoring (ConMon) process is grounded in NIST SP 800-137 and targets three primary objectives: "operational visibility; (ii) managed change control; and (iii) attendance to incident response duties." ## Three Core Process Areas **Operational Visibility** CSPs implement security controls like system monitoring and event logging, delivering monthly, annual, and triennial reports with supporting evidence. Control requirements reference the FedRAMP Security Controls Baseline workbook. **Change Control** Given cloud systems' dynamic nature, CSPs must conduct security impact analyses before implementing changes and follow processes outlined in the Significant Changes section. **Incident Response** CSPs must maintain incident response plans and demonstrate capability to address security incidents and emergency directives, with guidelines in the Incident Communication section. ## Stakeholder Responsibilities - **CSPs**: Primary accountability for implementing, monitoring, and maintaining security controls documented in their System Security Plan - **Agency Authorization Officials (AOs)**: Review ConMon activities and make risk-based authorization decisions - **FedRAMP PMO**: Oversees operations and ensures material availability to leveraging agencies - **CISA**: Coordinates with FedRAMP PMO on directives - **Assessors**: Conduct initial and annual assessments; may include FedRAMP-recognized 3PAOs or agency IV&V teams ## Monthly Reporting Requirements CSPs must submit updated Plans of Action and Milestones (POA&M) and inventory monthly, along with vulnerability scan files and reports, enabling agency AOs to evaluate ongoing security posture sufficiency.
